# M02｜总部厨房楼与菜谱产业链

## 目标
用一座可探索的 2.5D 像素总部，把食材如何变成“菜单—菜谱—出菜流程”可视化。总部承载主线，玩家至少应访问两名员工电脑并完成两次关键反馈。

## 楼层/房间布局

```text
前台与食材接入 → 菜单分析中心 → 策略餐桌 → 家常厨房 → 出菜调度台
                                      ↘ 食品安全审批台
```

开放式平面优先，避免迷宫。每个区有独立色块、地标、一个核心大屏和 3–6 位可见员工。

## 部门与岗位

| 区域 | 员工 | 真实职责 | 主要产出 |
|---|---|---|---|
| 前台 | Fridgey、Chopper、Allergy、Timer | 结构化用户条件 | Brief |
| 菜单分析中心 | Pantry、Balance、Menu、WasteNot、Budget、Season | 判断可做菜、搭配、补买与消耗顺序 | 菜单草案 |
| 策略餐桌 | Menu、Balance、Pulse | 在时间/口味/成本中取舍 | 菜单决策 |
| 家常厨房 | Wok、Oven、Prep、Sequence、Dishless、Plate | 把菜单做成步骤和并行时间线 | 做法草稿 |
| 调度与审批 | Pulse、Sentinel、Human Owner | 交接、质量门禁、发布 | 已确认任务包 |

## 三个核心电脑交互

### Pantry：食材分析台
展示可用食材、优先消耗食材、缺少项和不建议使用项。玩家选择“优先清冰箱”或“优先口味完整”。选择改变补买清单、剩余食材和菜式模板。

### Menu：菜单拼盘墙
玩家从两个合理菜单方向中选择：例如“快手下饭”或“轻食一锅”。每项选择呈现总耗时、锅具数、补买项和口味关键词；不做唯一正确答案。

### Sequence：出菜调度屏
玩家确认“同时出菜”还是“先主菜后配菜”。系统据此选择并行/串行时间线，并显示每一步使用的锅具与等待时间。

## 交接事件

```text
brief.confirmed
→ ingredients.analyzed
→ menu.drafted
→ menu.preference.confirmed
→ recipe.sequence.drafted
→ rnd.solution.attached
→ safety.review.requested
```

每个事件均有：角色位置、任务物件、状态气泡、右侧事件摘要四种表现。动画仅在事件发生时播放。

## 场景与幽默

- 风味组合墙会阻止明显荒谬但无害的组合，并用“需伦理委员会复核”的幽默提示；
- WasteNot 在临期食材边上贴优先级便签；
- Dishless 统计当前方案需要的锅具数量；
- Pulse 的控制台显示“人类输入缺失”，而非假装团队继续工作。

## 验收
- 玩家能一眼区分菜单分析、做法制作和审批；
- 点击电脑后的文字以正常 UI 呈现，不依赖像素字体；
- 从前台到厨房的任务状态与玩家选择一致；
- 至少一个选择改变菜单，一项选择改变时间线；
- 未完成用户反馈时，任务不能伪装为已完成。
