# M03｜家常菜谱、结果卡与用户反馈

## 目标
把公司内部的菜单和做法转化为用户能立即使用、能理解边界、能带走分享的“今晚开饭任务卡”。结果必须强调这是基于活动模板的灵感，而不是保证成功的专业指导。

## 结果页结构 `/play/result/[session]`

1. **今晚菜单**：2–3 道菜；每道显示使用的现有食材、可选补买项、时间与锅具。
2. **一条时间线**：按分钟列出切配、下锅、等待、出菜；支持“简洁版/详细版”。
3. **少洗锅/快手方案**：本局研发部提供的可执行技巧。
4. **替代与安全提示**：忌口替代、生熟分开、变质食材不使用、肉蛋海鲜充分熟制等。
5. **你的决策轨迹**：人数、时间、目标、菜单方向、研发偏好；让玩家看到反馈确实改变结果。
6. **AI 团队交接回放**：谁做了什么、何时等待用户、何时被审查。
7. **结果操作**：下载 PNG、生成分享链接、再玩一次、探索园区、了解真实服务（若存在）。

## 菜谱卡字段

```text
RecipePlan {

  prep_steps[], cook_timeline[],
  pain_point_solution, substitutions[], safety_notes[],
  assumptions[], decision_tags[], template_version
}
```

## 用户反馈机制

### 过程反馈
玩家每次在员工电脑中作答后，右侧抽屉更新：

```text
你决定了：优先少洗锅
影响：菜单改为单锅路线；预计洗锅由 3 次降至 1 次
下一步：ZeroWash 正在提供锅底风味复用方案
```

### 结果反馈
结算页仅提供低摩擦问题：

- 这份方案是否让你更容易决定今晚吃什么？
- 哪一部分最有帮助？菜单 / 时间线 / 少洗锅 / 园区探索
- 可选：一句匿名建议。

反馈与玩家身份分离；不把“满意度”伪装成真实菜谱验证。

## 分享设计
生成的分享卡包括：任务名、菜单名称、总耗时、锅具数、玩家选择的研发路线、虚构 Mission 编号和“活动模拟”小字。分享链接只携带模板 ID、分支标签和随机会话 ID；不包含用户原始食材文本、忌口或昵称。

## 质量门禁
Sentinel 在发布前检查：

- 忌口标签没有冲突；
- 时间线与选定厨具匹配；
- 不鼓励食用来源不明/变质食材；
- 不宣称营养疗效；
- 对不可确认输入显示假设而不是编造事实。

检查不通过时，结果卡显示“需要补充确认”，并回到对应员工面板。

## 验收
- 用户可以不用回看办公室就读懂并执行基础步骤；
- 结果明确显示时间、锅具数、替代项和安全提醒；
- 每个本局决策可在结果卡中找到影响；
- 分享不会泄露自由文本或敏感选择；
- 结果页在移动端单手浏览可读。
