# M14｜预制菜城市定点配送小厨房

## 目标
补全“中央工厂—城市节点—用户”的最后一公里。小厨房是城市内的模拟履约站：接收中央工厂的预制餐盒，做最后复热、组合、质检和定点配送准备。它与中央预制菜工厂不同，不承担大规模生产。

## 城市节点地图

```text
中央预制菜工厂
  → 冷链干线运输
  → 城市定点小厨房（North / Central / South，演示节点）
  → 社区自提柜 / 合作餐桌 / 定点配送
```

首版只开放一个“Central Kitchen”可探索，其他城市点以地图标记存在，避免制造复杂路由玩法。

## 岗位

| 岗位 | 任务 | 关键边界 |
|---|---|---|
| Hub Receiver | 接收模拟冷链批次 | 温度/批次异常则隔离 |
| Reheat Lead | 控制复热或最后组合步骤 | 不替代真实食品安全 SOP |
| Order Assembler | 将餐盒按模拟订单组合 | 不读取用户私人任务 |
| Local QA | 出发前检查标签、封签、过敏原 | 异常不能出站 |
| Route Dispatcher | 派发定点配送/自提路线 | 只显示虚拟路线 |
| Community Host | 管理合作餐桌/公益发放说明 | 不展示真实受助者数据 |

## 玩家互动

1. **冷链收货门**：点击看“批次—温控—可用状态”的简化关系；
2. **复热试验台**：看到预制菜为何有些步骤留给用户完成；
3. **配送地图**：小车从 Central Kitchen 到虚拟社区点；
4. **异常演练**：温度异常时 Local QA 把餐盒送入隔离区，系统通知 SAP 与工厂模拟中心。

## 数据与事件

```text
factory.batch.released
→ cityhub.batch.received
→ cityhub.quality.checked
→ cityhub.order.assembled
→ cityhub.dispatch.ready
→ demo.delivery.completed
```

所有订单、位置、温度和时间均为模拟或已授权聚合数据；不提供骑手轨迹、住址、顾客身份或实时商用配送承诺。

## 验收
- 玩家可理解小厨房与中央工厂的职责差异；
- 异常批次无法进入配送动画；
- 地图不会暗示实时追踪个人或送餐人员；
- 模块能从工厂、SAP 和食安实验室三处跳转进入。
